# Предварительная архитектура 1C FullStack

Статус: проектирование. Сервисы, образы и pipeline пока не реализованы.
Документ описывает целевую схему, а не проверенное рабочее окружение.

## Окружение и компоненты

Разработка ведётся на Windows с Ubuntu 24.04 в WSL2, Docker Desktop
с интеграцией WSL и Visual Studio Code.

| Компонент | Предполагаемая роль | Версия / статус |
| --- | --- | --- |
| Ubuntu в WSL2 | Рабочее окружение | 24.04, заявлено в описании окружения |
| Docker Desktop / Compose | Запуск изолированных сервисов | Выбрать и зафиксировать |
| 1С:Предприятие | Сборка и проверка конфигураций и расширений | Выбрать лицензированную версию |
| PostgreSQL для 1С | Хранение development и test баз | Выбрать после проверки совместимости с 1С |
| Jenkins | Оркестрация CI/CD | Выбрать и зафиксировать |
| GitHub | Исходный код и review изменений | Облачный сервис |

Перед добавлением исполняемых конфигураций необходимо проверить официальную
матрицу совместимости конкретной платформы 1С, сборки PostgreSQL и базовой ОС.
Совместимость сейчас не подтверждена. Образы должны иметь точные теги версий,
а при возможности — digest; тег `latest` не допускается.

## Поток изменений

1. Разработчик меняет исходники в отдельной Git-ветке.
2. Изменения проходят review в GitHub.
3. Jenkins получает код через отдельно настроенный механизм доступа.
4. Pipeline выполняет статические проверки, затем сборку и runtime-проверки
   в выделенном тестовом окружении.
5. Интеграционные проверки подтверждают взаимодействие 1С и PostgreSQL.
6. Результаты и разрешённые артефакты сохраняются с ограниченным сроком хранения.

Доступ Jenkins к GitHub, webhook и credentials ещё не настроены.
Автоматическое обновление production не входит в текущий этап.

## Изоляция и хранение

- Development и test используют отдельные базы, учётные данные и volumes;
  имена и Compose-проекты будут определены при реализации.
- Данные PostgreSQL и Jenkins хранятся вне Git в выделенных volumes.
- Тестовые задания не получают доступ к production.
- Секреты передаются через хранилище credentials Jenkins либо внешнее
  хранилище секретов. Локальные `.env` не отслеживаются Git.
- Лицензии и дистрибутивы 1С предоставляются отдельно законным способом;
  в репозитории их нет.
- Удаление volumes и баз запрещено правилами проекта. Перед обновлениями
  production требуются подтверждение и проверенный backup с восстановлением.

## Границы проверок

- Статические: структура, формат конфигураций, diff, отсутствие секретов
  при review. Не требуют запуска сервисов.
- Runtime: фактический запуск сервисов, healthcheck, доступность процессов.
- Интеграционные: подключение 1С к тестовой PostgreSQL, выполнение pipeline,
  сборка и проверка тестовой конфигурации или расширения.

Runtime- и интеграционные проверки пока не реализованы и не выполнены.
Открытые вопросы: версии и совместимость компонентов, лицензирование 1С,
источник образов, ресурсы WSL2, управление секретами и политика backup.
